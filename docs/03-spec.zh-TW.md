## 2. 技術架構

### 2.1 技術選型

| 項目 | 選擇 |
|---|---|
| 語言 | TypeScript |
| 建置 | Vite |
| 遊戲引擎 | Phaser 3（開工時鎖定一個穩定版本號） |
| 地圖編輯 | M2 前：程式定義（`src/data/world.ts`）；M2 起：Tiled（輸出 `.tmj`） |
| 文字介面 | DOM 疊在 canvas 上（HUD、對話框、機台視窗、圖鑑、證據簿） |
| 劇本格式 | YAML，中英文並排 |
| 測試 | `bun test`（系統邏輯，介面測試用 happy-dom）＋手動試玩清單 |
| 環境需求 | Bun 1.4.3（用 winget 以使用者範圍安裝） |

### 2.2 目錄結構

```
D:\g\
  docs/                 企劃、故事、規格、路線圖（中英各一份）
  mockups/              原型，保留作為參考
  game/
    index.html
    package.json
    vite.config.ts
    src/
      main.ts
      scenes/           Boot、Title、World、ChapterCard、Ending
      systems/          sanity、codex、evidence、relations、ask、clues、story、save、i18n
      render/           tool（黑機台）、leds（光點）、person（人物）
      ui/               hud、dialog、toolWindow、codex、evidence、settings
      data/
        maps/           *.tmj
        cases/          case03.json
        story/          prologue/*.yaml、ch02/*.yaml
        codex.yaml
        locales/        ui.zh-TW.json、ui.en.json
    public/assets/      圖塊、角色、頭像、字型
    tests/
```

### 2.3 資料驅動

- **劇本：** 每個場景一個 YAML。每一行對話同時有 `zh` 和 `en`，翻譯不會對不起來。格式見附錄 A。
- **案件：** 每個案件一個 JSON，包含 SPC 點、log、耗材、wafer 參數、線索對應、正解、最少線索數。
- **介面文字：** `locales/ui.*.json`，用 key 取字串。
- **規則：** 程式碼裡不寫死任何玩家看得到的文字。

### 2.4 存檔

- 存在瀏覽器 `localStorage`，一個存檔欄位，外加「新遊戲」。
- 換場景和章節結束時自動存檔。
- 存檔內容：章節、場景、旗標、理智、咖啡、關係值、已解鎖的圖鑑、證據、線索、主角名字、設定。
- 讀不到或格式錯誤時，回到標題畫面並提示，不讓遊戲當掉。

### 2.5 畫面與效能

- 圖塊 16×16 px。像素整數倍放大：畫面寬 ≥1500px 放大 4 倍、≥840px 放大 3 倍，其餘 2 倍（沿用原型）。
- 目標 60 fps。畫面外的機台不繪製 LED。
- 支援瀏覽器：Chrome、Edge、Firefox、Safari 最新兩個版本。

## 5. 系統規格

### 5.1 移動與互動（沿用原型）

- 一格走 0.15 秒，四方向。
- 點地板自動尋路，點物件或人會走到旁邊並自動互動。
- 互動鍵：E／空白鍵／Enter；觸控有方向鍵和 A 鈕。
- 沒穿無塵衣不能通過風淋室。

### 5.2 理智值

- 範圍 0–100，序章開始時 80。HUD 顯示一條橫條和數字。

| 事件 | 變化 |
|---|---|
| PUA 台詞（依台詞強度） | −5 到 −15 |
| 同一句台詞辨識正確 | 該次損失減半（無條件捨去） |
| 留下來加班 | −5 |
| 準時下班 | ＋3 |
| 設界線 | ＋5 |
| 和盟友聊天（每章每人一次） | ＋5 |
| 結論錯誤 | −5 |
| 完成章節 | ＋10 |

- **歸零：** 第一次觸發「強制請假」事件（跳到隔天，理智回到 40，王經理傳一句酸話）。第二次進入「燃盡」結局。

### 5.3 話術辨識

1. 劇本裡標有 `tactic` 的台詞出現時，對話框右上角出現「？」按鈕，持續到這句話結束。
2. 玩家按下「？」，跳出圖鑑卡片選單。已解鎖的卡顯示名稱，未解鎖的顯示「？？？」，但仍然可以選。
3. 選對：該次理智損失減半，該卡解鎖，跳出一句說明。選錯：沒有懲罰，也沒有減傷。
4. 序章 S6 第一次出現時有教學引導。

**v0.1 的 7 張卡：** 雙重束縛、否定人格、拿人比較、大家庭、為你好、搶功、煤氣燈。

### 5.4 證據簿

- **自動記錄：** 劇本裡標有 `evidence: true` 的台詞和訊息，會自動存進證據簿。
- **手動記錄：** 每句對話都有「記下」按鈕，玩家可以自己存。
- 每筆證據包含：ID、遊戲內時間、來源（對話、LINE、會議）、說話者、內容（中英）、標籤。
- 第 2 章晨會的選項會檢查證據簿裡有沒有特定 ID（見 7.2）。

### 5.5 關係值

- 每位 NPC 一條，範圍 −100 到 100。
- 「問人」的結果依關係值決定：

| 有效關係值 | 結果 |
|---|---|
| ≥ 20 | 完整回答 |
| 0–19 | 部分回答 |
| < 0 | 不回答，或用話術回應 |

- 選擇「先說我查過什麼」時，有效關係值 ＋15。

### 5.6 問人系統

- 每個「問題主題」有一個 ID，例如 `hold_lot`。每位 NPC 對每個主題都有一組三段回答（完整／部分／拒絕）。
- 問完會設定旗標，例如 `knows_hold_lot`，劇情依旗標推進。
- 序章 S5 解鎖技能「問人技巧」後，問人選項多出「先說我查過什麼」。

### 5.7 回應選項

話術事件之後的四種回應：

| 回應 | 理智 | 對施加者的關係 | 備註 |
|---|---|---|---|
| 吞下去 | −3 | ＋5 | 什麼都沒改變 |
| 澄清事實 | ＋0 | −5 | 需要相關證據才會有效 |
| 設界線 | ＋5 | −10 | 長期效果最好 |
| 找人討論 | ＋5 | ＋0 | 該盟友關係 ＋5 |

### 5.8 線索與結論（沿用原型，改成讀資料檔）

- 點選可疑的資料，記進線索簿。
- 提交結論需要至少 3 條線索。
- 結論錯誤：咖啡 −1、理智 −5，可以重來。

### 5.9 咖啡值

- 範圍 0–5，只在夜班時每 2 分鐘（真實時間）−1。
- 辦公室咖啡機 ＋1。
- 咖啡歸零時，移動速度 ×0.7，並跳出「好睏……」。

### 5.10 設定

| 項目 | 選項 |
|---|---|
| 語言 | 繁體中文／English，隨時切換、立即生效 |
| 文字速度 | 慢／標準／立即 |
| 減少動態效果 | 開啟時停用 LED 閃爍、跑馬燈、紅光閃爍；也會跟著系統的「減少動態效果」設定 |

## 9. 驗收標準

v0.1 完成的定義：

1. 從標題畫面「新遊戲」開始，可以不卡關玩到「試玩結束」卡，繁中和英文各完整走一次。
2. 遊戲進行中切換語言，畫面上所有文字（包含對話、機台視窗、圖鑑）立即換成另一種語言，沒有漏翻。
3. 理智、關係值、證據、圖鑑、線索都正確存檔；重新整理頁面後按「繼續」，狀態完全相同。
4. 理智歸零的兩段流程（強制請假、燃盡結局）都能觸發。
