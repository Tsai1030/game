## 1. 總覽

工作量用相對大小表示：S（小）、M（中）、L（大）、XL（特大）。實際時間要看投入的人力，先不估週數。

| 里程碑 | 名稱 | 內容 | 工作量 | 產出 |

| M0 | 基礎建設 | 版本控制、開發環境、把原型搬進正式架構 | S | 跟原型一樣能玩，但已經是正式程式碼 |
| M1 | v0.1 試玩版 | 範圍 A：序章＋第 2 章＋劇情系統＋中英切換 | L | 可以給人試玩的完整一段 |

## 2. M0 · 基礎建設（S）

> **狀態（2026-10-20）：完成。** 負責人手動試玩沒有發現問題，已合併進 `main`。73 個自動測試通過、型別檢查通過、建置成功。實作計畫與進度見 `docs/superpowers/plans/2026-10-20-m0-foundation.zh-TW.md`。改用 Bun（使用者指定），地圖格式延到 M2（見規格書第 0 節）。

**要做的事：**
1. 在 `D:\g` 執行 `git init`，提交目前的 docs 和 mockups。
2. ~~安裝 Node.js LTS~~ → 改為安裝 Bun（使用者指定）。
3. 在 `game/` 建立 Vite＋TypeScript＋Phaser 3 專案。
4. 把原型搬進新架構：廠區地圖、移動與尋路、黑機台＋LED、機台視窗、線索簿、結論。
5. 建好資料管線：YAML 劇本讀取、案件 JSON、介面文字的中英切換。
6. 存讀檔、設定（語言、文字速度、減少動態效果）。

**完成條件：**
- 新架構可以玩完原型的 Case 03，畫面和原型一致。
- 隨時可以切換繁中／英文。
- 系統邏輯有測試，而且通過。

**需要使用者先同意的事：** 安裝 Node.js、在專案資料夾初始化 git。

## 3. M1 · v0.1 試玩版（L）

**要做的事：**
1. **劇情系統：** 理智值、話術辨識（7 張卡）、證據簿、關係值、問人系統、回應選項、劇情旗標。
2. **地圖：** 新增警衛室、新人訓教室、租屋處；廠區主地圖加上會議室和 OP 休息區。
3. **新角色：** 芳姐、Amy、大熊、陳處長、警衛。
4. **劇本：** 序章 S1–S8、第 2 章 C2-01 到 C2-10，中英文都寫。
5. **介面：** 標題畫面、章節卡、試玩結束卡、圖鑑、證據簿、理智條。
6. **結局：** 強制請假事件、燃盡結局。

**完成條件：** 規格書第 9 節的 8 條驗收標準全部通過。

## 4. M2 · 試玩與打磨（M）

**要做的事：**
1. **業內審閱：** 請一位 etch 製程或設備工程師，依規格書附錄 B 的清單審閱。
2. **試玩：** 找 5–10 位試玩者，以科技業從業者為主。每人玩完填一份簡短問卷（好不好玩、哪裡卡、哪句台詞最有共鳴、哪句最假）。
3. **匿名台詞徵集：** 收集真實聽過的話術，挑選後改寫進劇本。
4. **美術決定：** 三選一：
   - 維持程式繪製風格，只做細修
   - 購買授權的像素素材包，再改成黑色系
   - 委託像素畫師
5. **音效與音樂：** 機台運轉聲、alarm、腳步、對話嗶聲、夜班環境音。
6. 依回饋修正，輸出 v0.2。

**完成條件：** 審閱和試玩回報的問題都已分類，嚴重問題全部修正。

## 5. M3 · 範圍 B（L）

**要做的事：**
1. **第 1 章：** 第一次值班（Case 01：量測偏移）。
2. **第 3 章：** 皮球（particle 異常），加上三角操作劇情。
3. **設備工程師玩法「機台 Down！」：** alarm、查手冊、換零件、復機。可以從第 3 章切換到大熊操作。
4. **圖鑑新增卡片：** 只否定不給標準、移動球門、三角操作（累計 10 張）。
5. 角色切換系統。

**完成條件：** 序章到第 3 章可以連續玩完；切換角色時，狀態保存正確。

---

## 6. M4 · 範圍 C（XL）

**要做的事：**
1. 第 4–7 章的地圖、劇本和案件。
2. **裝機工程師玩法「交機倒數」：** move-in、sub-fab 配管解謎、上電、SAT。
3. **圖鑑最後 3 張卡：** 畫大餅、情緒勒索、冷處理（共 13 張）。
4. 5 種結局，包含隱藏結局「共好」。
5. 第 7 章的「鏡子」對話系統：你聽過的話，與另一種說法。

**完成條件：** 完整第一年可以玩完；5 種結局都能觸發；中英文完整。

---

## 7. M5 · 上市準備（M）

**要做的事：**
1. **專業審閱：** 請心理或勞動相關的專業人士審閱圖鑑和敏感橋段。
2. **求助資源：** 依上市地區查證申訴管道、諮商資源，放進遊戲選單和片尾。
3. **在地化檢查：** 請英文母語者讀一遍英文版。
4. **效能與相容性：** 各瀏覽器和手機實測。
5. **發佈：** 選擇平台（例如 itch.io 網頁版或自架網站），製作宣傳頁和截圖。

**完成條件：** 審閱意見處理完畢，正式上線。

## 8. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 製程細節不夠真 | 目標玩家（業內）出戲 | M2 業內審閱；台詞徵集 |
| PUA 題材處理不當 | 讓受過傷的玩家不舒服，或被認為在美化 | 遵守故事線的立場與寫作守則；M5 專業審閱；附求助資源 |
| 範圍膨脹 | 遲遲做不完 | 嚴格照里程碑；先完成 v0.1 再擴充 |
| 美術工時 | 內容卡在等圖 | v0.1 先用程式繪製，M2 再決定 |
| 中英文不同步 | 某一語言漏翻或意思跑掉 | 劇本 YAML 中英並排；驗收標準要求兩種語言各玩完一次 |
| 開發環境 | 這台電腦沒有 Node.js | M0 第一步就安裝 |
